# DT-93 .. DT-106 — Engine V3 (Alpha + Beta)

Authorized by **D-030** (2026-07-27). DEF-003 re-scoped to gate public quality claims
only, so product advancement no longer waits on a listening study that cannot be run.

## Standing rules for this track

1. **The owner is not a gate.** Milestones complete on automated technical safety, graph
   validity, and mode-distinctness evidence. Rendered audio is written to an accessible
   location for optional review; execution never pauses waiting for a reaction.
2. **Primitives are not finished processors.** Exposing a pedalboard plugin removes a
   dependency/licensing barrier, nothing more. A processor is done when it is tuned,
   bounded, rendered, and its behavior verified.
3. **Name capabilities honestly.** No component or UI label may claim a capability the
   code does not implement. Specifically: reverb built on the generic `Reverb` plugin is
   described as *tuned generic reverb*, never "plate", until a true plate implementation
   exists; `PitchShift` is *transposition*, never "tuning", "pitch correction", or
   "Auto-Tune"; the `NoiseGate` is a *gate*, never "denoising"; there is no
   dereverberation until DT-101 ships one.
4. **Hard safety is unchanged**: no clipping, no non-finite samples, no destroyed
   duration, no catastrophic gating, `-0.2 dBFS` attenuate-only ceiling preserved.
5. **No public claims.** Bold processing is a creative default, not a quality assertion.

## Relationship to prior findings

N-016 .. N-022 remain authoritative **about measurement**. They established that the
automated search objective is gameable and not perceptually grounded. That conclusion is
untouched here and continues to bar objective-driven promotion claims.

It does not bar building processors and modes a human can listen to: the objective is only
required when an *automated search* selects parameters. Mode chains are authored, bounded,
and safety-checked — they do not depend on Q-016 being resolved.
